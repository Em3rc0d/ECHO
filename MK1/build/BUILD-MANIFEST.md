# MK1 Build Manifest Specification

**Status:** `SPECIFICATION_FROZEN / VALUES_PENDING_BUILD`

## Purpose

Capture the exact identity of a build/test run so results are reproducible and comparable.

## Manifest fields

```yaml
schema_version: echo.build-manifest.v1
build_id: ...
git_commit: ...
built_at_utc: ...
runtime:
  os: ...
  python_or_runtime: ...
  dependency_lock_sha256: ...
tools:
  ffmpeg_version_build: ...
  broker_version: ...
data:
  dataset_manifest_sha256: ...
  split_manifest_sha256: ...
model:
  model_id: ...
  checkpoint_sha256: ...
  preprocessing_version: ...
config:
  source_config_sha256: ...
  event_engine_config_sha256: ...
  publisher_config_sha256: ...
schemas:
  inference: ...
  event: ...
hardware:
  cpu: ...
  gpu: ...
  ram: ...
```

## Secrets

Manifest stores references or redacted identities, never credentials/tokens.

## Usage

Benchmark, streaming replay and E2E reports cite `build_id`. A model comparison without equivalent build/data identities is not certified.

## Integrity

Artifacts too large for Git use hashes and canonical storage/origin references. Missing checkpoint/data hash makes the result non-reproducible.

## Invalidation

Changed dependencies, model/config/data/schema create a new build ID rather than editing historical manifests.
